## The Pi

- Raspberry Pi OS Lite 64-bit; the app runs as the systemd service `led-matrix`.
- Hostname and user are whatever was chosen in the Raspberry Pi Imager; the
  Pi is reached as `<user>@<hostname>.local` on the home network.
- The app is TypeScript and runs on Node; the only Python left is the small
  panel driver (`pi/panel_driver.py`) and the sprite script.
- The pet page (`app/pet.html`, `app/src/`) is also the app for the phone,
  with its pet on the phone or on a Pi; Capacitor packs it for the stores
  (`app/android/`, `app/ios/`). See *The app* in the README.
- Checking and testing without root is fine (reading logs,
  `systemctl status led-matrix`, starting the app with the dummy matrix, …).
- A change reaches the Pi through `setup.sh --app` (see *Running it* in the
  README); it needs sudo.
- Personal details for a specific Pi (address, who runs sudo, how updates are
  deployed) belong in `CLAUDE.local.md`, which is not checked in.

## Rules

- **Everything goes through `setup.sh`.** Whatever is installed or configured
  on the Pi goes into the setup script, never as one-off manual commands. A
  fresh Pi must be reproducible from the repo alone.
- **Home network only.** Nothing is ever exposed to the internet (no port
  forwarding, tunnels or public services).
- **English only.** Everything written in the repo is English: comments,
  docstrings, log messages, commit messages, docs and new files.
- **No UI text in code.** Text shown to users (pet page, web interface, panel)
  goes into the language files (`app/locales/`, see
  [docs/translating.md](docs/translating.md)), never hard-coded. A new text
  is added to `en.json` and `de.json` in the same change.
- **Every language reads as if written in it.** Each language's texts (app,
  store listings and screenshot captions, docs) are written the way a native
  speaker would say them, not translated word for word from another language:
  plain everyday words, the language's own idioms and sentence order. Each
  text says one thing; a caption describes what the picture is about rather
  than listing what is in it.
- **Creature names follow *Naming a creature*** in
  [docs/translating.md](docs/translating.md): a name of a kind, melted from
  words that fit it, no real word and no first name; every language gets
  names of its own.
- **Sprites come from the script.** The sheets in `app/pet/assets/` (PNG and
  JSON) are generated by `tools/build_blob_sprites.py`. Edit the pixel art
  there and run the script; never change the generated files by hand. The
  same goes for the sounds in `app/pet/sounds/`: their recipes are in
  `tools/sfx.ts`, and `npm run sounds` writes them.
  Things drawn next to the pet keep the sizes in *Sizes of things next to
  the pet* in [docs/gameplay.md](docs/gameplay.md).
- **New creatures follow the design rules** in *Designing a creature* in
  [docs/gameplay.md](docs/gameplay.md): two ideas, a creature rather than
  an object with a face (an animal or a living thing), a face of its own,
  body language, three colors, a way of moving that fits it, and it shows
  its character and where it came from. The forms of a line stay the same
  kind of creature, and growing up is something to look forward to. The
  adults of a line differ in shape, not just color; the second idea changes
  the body instead of being a hat or a tool; and the secret form stands
  above the other adults, not beside them: the legendary version of the
  line, its feature grown beyond the others, the biggest form, with an
  effect of its own.
- **No spoilers outside `docs/pets.md`.** Which forms a pet can grow into is
  for players to find out. Pictures and text in the README and the other docs
  show only egg, baby, child and Angloop, as the one example of an adult.
  The other adult forms, every form of a later line, and all rules for getting
  a form appear only in [docs/pets.md](docs/pets.md), folded shut.
- **No personal data in the repo:** no names, addresses, hostnames, IPs,
  tokens or keys. The one exception is the app's public contact: in the
  privacy policy and support page (`docs/privacy*.md`, `docs/support*.md`),
  which the stores require, and its address as the recipient of failed builds
  in `codemagic.yaml`.
  `config.ini` holds local settings and is not in Git;
  `config.example.ini` is the template.
- **The app explains itself.** If something in the app needs a sentence to
  explain how to use it, change how it works instead of adding the sentence:
  a tap does the obvious thing, the pet answers on the scene, and hints are
  feedback after a try, not instructions before it. Text that belongs to the
  game world (a poster, a letter, a sign, what the pet tells) is welcome;
  only instructions for using the app are avoided.
- **Ask before rebooting the Pi.**

## The API between app and Pi

The app from the stores and the Pi are updated apart (store review takes days,
a Pi updates itself within hours), so an app often talks to an older or newer
Pi. Two numbers in `core/src/api.ts` say what fits; every pet answer carries
them, and the app shows "update the display" or "update the app" when they
don't fit:

- **`API_VERSION` + 1** with every change the app may rely on: a new route,
  action or field of the pet's answers.
- **`API_OLDEST` = `API_VERSION`** as well when something an older app relies
  on is removed, renamed or changes its type.

`core/test/api.test.ts` compares the API with `core/test/api-contract.json`,
fails with the number a change needs, and once it is raised, the contract is
written anew with `UPDATE_API_CONTRACT=1 npm test -- api`. Commit both.

## Keep the docs in step

Docs are part of the change, not a follow-up:

| Change | Update |
|---|---|
| Game rules, values, what the pet can do | [docs/gameplay.md](docs/gameplay.md); the feature list in the README if it is visible there |
| A form of the pet, or the rule for getting it | [docs/pets.md](docs/pets.md), with everything that spoils kept inside `<details>` |
| An idea from the roadmap is built, or dropped | Its issue |
| Setup, paths on the Pi, new or moved files | [README](README.md) (including the tables under *Running it* and *Development*) |
| A setting is added or changed | `config.example.ini` and the *Configuration* table in the README |
| Hardware or wiring | [docs/hardware.md](docs/hardware.md) |
| What the app stores, sends over the network, or asks permission for (a new server, permission, data kind or backup behavior) | [docs/privacy.md](docs/privacy.md) and `privacy.de.md` (date at the top); remind the owner that the data declarations in Google Play (*Data safety*) and App Store Connect (*App Privacy*) need the same change |
| The contact address | `docs/privacy*.md`, `docs/support*.md` and `codemagic.yaml` |
| How the scene looks | Regenerate `docs/pet_preview.png` with `--spoiler-free` (below) |
| How a form of the pet looks | Regenerate `docs/images/pets/` (below) |

## Tests and preview

```bash
npm test && npm run check    # tests and type check of core/, pi/ and app/
```

After a change to game rules or values that decide when eggs, forms or
stats come (care, decay, finds, friends, eggs, the rules for a form), run the
balance checks and compare with the last run; mention what moved in the PR:

```bash
npm run balance        # pets played for three weeks by owners of different kinds
npm run collection     # a whole home played for months: when each line's eggs and forms come
```

Both name the adult forms in their output, so their results stay out of the
repo and the public docs.

After a change to the scene or the sprites, render the preview and look at
it (for the clock and the temperature it needs `LED_MATRIX_BDF_DIR`, the
fonts folder of rpi-rgb-led-matrix):

```bash
npm run preview                     # all states → pet_preview.png
npm run preview -- --spoiler-free   # one adult form and the first area only, for the docs
npm run preview -- play --gif       # one animation → pet_play.gif
npm run preview -- --pets           # one picture per form → docs/images/pets/
```

The overviews and the GIF land in the current folder. Look at the full
overview, but check in the spoiler-free one as `docs/pet_preview.png`.
